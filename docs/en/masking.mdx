---
title: Data masking
description: Data masking hides selected fields or recognized sensitive values before a response reaches the client.
sidebar:
  order: 12
---

Masking hides sensitive values without replacing the entire response. For known JavaScript Object Notation (JSON) fields, name the fields to hide. Data Guard detects supported credit card and Social Security number formats. Use synthetic data to test either mechanism.

| Mechanism | Selection | Expected change |
| --- | --- | --- |
| Sensitive-data disclosure rule | GET `/sensitive` and named JSON fields | Selected values are hidden; other fields remain usable. |
| Data Guard rule | `/sensitive` with an attached application firewall | Supported sensitive values are masked in the selected response. |

## Selected JSON fields

> **Visitor response:** The JSON response keeps its structure but hides the values of `card` and `ssn`.

The `sensitive_data_disclosure_rules` entry matches GET `/sensitive`, names `card` and `ssn` in `body.fields`, and selects `mask`. The replacement text can vary; check that the original values are gone.

## Data Guard

> **Visitor response:** Supported credit-card and Social Security numbers are masked.

The `data_guard_rules` entry matches `/sensitive` and selects `apply_data_guard`. The path rule does not define new recognition patterns. Data Guard requires an application firewall attached through the load balancer's `app_firewall` reference.
