Bot Defense Standard can block a classified request or redirect its caller to help. These examples are inactive and configuration-only; they do not establish runtime classification or mitigation.

Both alternatives describe secure HTTP POST `/bot-check` for web clients, allow good bots, use the US regional endpoint, and insert asynchronous JavaScript after the head element. `mitigation.block` and `mitigation.redirect` are exclusive choices.

## Block response

> **Visitor message:** Request not accepted.

The protected endpoint selects `mitigation.block` with `status: Forbidden` and an encoded body. The body has a 4,096-character limit including its prefix. The example does not expose a confirmed `Content-Type` field. See [response-body encoding](../configuration-reference/#response-body-encoding) for the placeholder.
