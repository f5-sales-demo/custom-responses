## Purpose

Give callers useful response metadata and remove values that should not leave the origin. F5 Distributed Cloud can transform Hypertext Transfer Protocol (HTTP)
response headers and cookies on a load balancer. This lets you identify an application response, control cookie attributes, or remove obsolete origin metadata
without replacing the application's page.

Headers and cookies affect client behavior as well as diagnostics. Select values deliberately and check that the transformation preserves the response status and content your application needs.

## When to use it

Use this when the origin emits a header or cookie that needs consistent handling at the edge. You need an existing load balancer and a test origin returning known metadata. The example adds `x-showcase`, removes `x-origin-remove`, adds a `showcase` cookie and removes `origin-remove`.

The added cookie uses path `/`, Secure, HttpOnly and SameSite Lax. These attributes govern where browsers send or expose the cookie; check them in the actual response. An edge transformation does not itself establish a login session or application authorization.

## Configure it

1. Set `response_headers_to_add` for headers callers should receive.
2. Set `response_headers_to_remove` for unwanted origin headers.
3. Set `response_cookies_to_add` with the cookie value and intended attributes.
4. Set `response_cookies_to_remove` for cookies that should be removed.

The example sets `append: false` for the added header and `overwrite: true` for the added cookie. Review those choices when an origin already sends the same names. The fragment is Terraform JavaScript Object Notation (JSON); its outer array represents the `more_option` provider block.

## Expected behavior

The example expects the origin's `200` status and normal body to remain intact. The response should include `x-showcase: custom-responses` and omit `x-origin-remove`. Its `Set-Cookie` values should include `showcase=custom-responses` with the configured attributes, while omitting `origin-remove`.

This transformation is configured for the load balancer rather than a dedicated path. Requesting `/` twice on that same host does not provide an untransformed comparison. Use the separate control host or your authorized origin path to inspect the original metadata.

## Check the result

Request `/` on the transformed host and inspect response headers and every `Set-Cookie` field. Confirm additions, removals and cookie attributes while checking status `200` and the unchanged body. Compare `/` on a control host that uses the same origin without these transformations; the original removable values should be visible there.
