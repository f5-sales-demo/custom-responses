When Bot Defense Standard selects mitigation for a protected endpoint, it can block the request or redirect the visitor to a help page. These examples are inactive and configuration-only; they do not demonstrate live classification or mitigation.

Both examples protect POST `/bot-check` over a secure connection for web clients. They allow good bots, use the United States regional endpoint, and insert asynchronous JavaScript after the page's `<head>` element. Each endpoint chooses either `mitigation.block` or `mitigation.redirect`.

## Block response

> **Visitor message:** Request not accepted.

The block alternative uses `mitigation.block` with `status: Forbidden` and an encoded body. The body has a 4,096-character limit including its prefix. The Bot response has no confirmed `Content-Type` setting. See [response-body encoding](../configuration-reference/#response-body-encoding) for the placeholder.
