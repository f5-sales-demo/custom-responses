A policy can select browser or human verification for a sensitive path. Application-layer distributed denial-of-service (DDoS) mitigation can select JavaScript verification during an active mitigation event. These are separate alternatives.

| Alternative | Selector | Comparison |
| --- | --- | --- |
| Policy JavaScript | Exact `/challenge` rule | `/` bypasses verification. |
| Policy CAPTCHA | Exact `/challenge` rule | `/` bypasses verification. |
| DDoS JavaScript | Active application-layer mitigation | Normal traffic outside the event. |

See [response-body encoding](../configuration-reference/#response-body-encoding) for the custom-page placeholder. Preserve platform-controlled challenge scripts and interactions.

## Policy-selected JavaScript challenge

> **Visitor message:** Please wait while your browser is verified.

`policy_based_challenge.js_challenge_parameters` supplies the page and parameters. A rule matching exactly `/challenge` selects `enable_javascript_challenge`; `no_challenge` is the default. Cookie expiry affects repeat visits.
