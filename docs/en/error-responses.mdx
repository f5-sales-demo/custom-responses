Give visitors a recognizable explanation when a request fails. The load balancer's error map selects a body by status class or exact status while preserving the response status.

## Prerequisites

An F5 Distributed Cloud Hypertext Transfer Protocol (HTTP) load balancer is the resource that receives application requests and selects routing or security behavior.

You need permission to edit an existing HTTP load balancer in its namespace and a test application you are authorized to configure. You also need a test origin that can return the statuses you select. Allow about 15–20 minutes for configuration, excluding provisioning and failure testing.

## Configure

### Choose an error mapping

| Mapping | Example message | Selection |
| --- | --- | --- |
| Class `3`, `4` or `5` | “Class 3”, “Class 4” or “Class 5” | Covers the corresponding status family. |
| Exact `503` | “Exact 503” | Takes precedence over class `5`. |
| Exact `404` | “Exact 404” | Takes precedence over class `4`. |

Class `3` replaces an eligible response body; it does not create a redirect or change its destination. Each encoded error-body value has a 65,536-character limit, including the prefix. Replace `<ENCODED_RESPONSE_BODY>` with your encoded message. See [response-body encoding](../configuration-reference/#response-body-encoding).

### Set a class fallback

> **Visitor message:** Class 3

1. Save the previous settings for the fields you change.
2. Add the status-class key to the load balancer's `more_option.custom_errors` map.
3. Set its value to the encoded class message.
4. Save the load balancer.

> **Visitor message:** Exact 503

## Verify

1. Request `/status/503` on the exact-status test host.
2. Confirm status `503` and “Exact 503” rather than “Class 5.”
3. Request `/status/500` on that host.
4. Confirm status `500` and the class fallback.
5. Compare `/` with the healthy `200` origin response.

Repeat independently for `404` and for class `3`, `4` and `5` using `302`, `418` and `500`. A connection reset, unavailable upstream or timeout can follow a different response path from an origin error. Check each failure you depend on; the edge examples expect `500`, `502`, `503` or `504` with “Class 5,” according to the failure actually produced.

For an edge-failure host, compare its failing `/` with `/healthy`, which selects a healthy origin pool.

## Clean up

Restore the previous `more_option.custom_errors` map. Remove only mappings and test routes you added. Preserve shared origin pools, existing routes and the load balancer. Confirm normal responses and your original error handling.
