Custom error mappings show a message for a status family or an exact code. The load balancer replaces the response body without changing the status.

| Mapping | Visitor message | Result |
| --- | --- | --- |
| `3xx`, `4xx`, or `5xx` (keys `3`, `4`, `5`) | “Class 3”, “Class 4”, or “Class 5” | Fallback for the status family. |
| Exact `503` | “Exact 503” | Overrides class `5` for `503`. |
| Exact `404` | “Exact 404” | Overrides class `4` for `404`. |

A mapping for key `3` can change the body of a `3xx` response; it does not create a redirect or change its `Location` header. Each encoded error body has a 65,536-character limit including the prefix. See [response-body encoding](../configuration-reference/#response-body-encoding) to create your own message.

## Exact status

> **Visitor message:** Exact 503 or Exact 404

A `503` mapping overrides key `5`, and a `404` mapping overrides key `4`. Other codes still use their family mapping.

## Edge failures

An upstream connection reset or timeout may produce a different status from an origin error. Check the actual status before expecting a mapped body: these examples can return `500`, `502`, `503`, or `504`.

The shared host routes `/fault/500`, `/fault/502`, `/fault/503`, and `/fault/504` to distinct test pools. Exact `503` takes precedence over class `5`; the other faults use “Class 5” when mapping applies. The `/` path reaches the healthy origin pool for comparison.
