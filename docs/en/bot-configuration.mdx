## Purpose

Choose how an application responds when Bot Defense Standard classifies traffic for mitigation. A block can explain that the request was not accepted; a redirect can send the caller to a help destination. The response is part of the Bot mitigation choice, which is separate from a route response or an application-firewall block.

Bot is configuration-only in this guide. Both examples are inactive, live outside the Terraform configuration directory, and are excluded from default resources. The examples explain the choices without claiming that a bot was classified, blocked or redirected in the demo.

## When to use it

Use the examples to review a prospective protected endpoint's response configuration. Bot Defense Standard entitlement and genuine classification are prerequisites for runtime behavior. Legitimate-browser checks are also needed before enabling mitigation in your own authorized environment.

Both examples protect secure Hypertext Transfer Protocol (HTTP) POST requests to `/bot-check` for web clients, allow good bots, select the US regional endpoint, and configure asynchronous JavaScript insertion after the head element. Block and redirect are exclusive mitigation choices for a protected endpoint. The redirect destination must exist and offer the intended help.

## Configure it

1. Review the protected endpoint's method, path and client selection.
2. Choose its `mitigation` block or redirect action.
3. For a block, set the status enum and encoded body.
4. For a redirect, set the destination URI.

These are inactive Terraform JavaScript Object Notation (JSON) examples with block arrays and unresolved Terraform references. They are not complete executable application programming interface (API) requests. The [configuration reference](../configuration-reference/) links to full source and optional operator activation requirements.

## Expected behavior

The block example configures `Forbidden` and “Request not accepted.” The redirect example configures a help URI; it does not establish a specific redirect status. The block body has a separate 4,096-character encoded-URI limit. No confirmed Content-Type field is exposed by this example.

These settings describe intended configuration. No runtime classification, status, media type, block or redirect is verified here, and configuration-only entries do not count as successful live tests.

## Check the result

For this scope, inspect the example: confirm the endpoint selects POST `/bot-check` and exactly one mitigation action. Compare the alternate example to
understand how its action differs. If runtime demonstration is added later, compare genuinely classified traffic with legitimate-browser requests and verify the
help destination before treating the mitigation as accepted.
