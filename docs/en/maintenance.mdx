## Purpose

Tell visitors that an application is temporarily unavailable and give them a clear next step. A direct response route on an F5 Distributed Cloud Hypertext
Transfer Protocol (HTTP) load balancer returns a fixed status and body for a matching path. The route can answer while the origin is unavailable, because it
does not need an origin response to create the page.

This is useful when maintenance is planned and you want a predictable message. You control both the path that selects the message and the response content. Visitors outside that path continue through the load balancer's other routes.

## When to use it

Use a maintenance response for a temporary service pause or a dedicated service-status path. The example selects `/maintenance` and returns `503`, the HTTP
status for service unavailability. You need an existing load balancer and access to its route configuration. Confirm route matching and precedence before
relying on the message for a larger application path.

A dedicated `/maintenance` path does not automatically intercept every request to your site. If your intended maintenance window covers more paths, select those paths deliberately in your own configuration. Keep a normal comparison path available so you can distinguish a selected direct response from a broader connectivity problem.

## Configure it

1. Select the path that should display maintenance information.
2. Add a `direct_response_route` with that path to the load balancer's `routes` list.
3. Set `route_direct_response.response_code` to the intended status.
4. Set `response_body_encoded` to the message body using the `string:///` encoding shown in the source.

This fragment is Terraform JavaScript Object Notation (JSON). Its arrays represent provider blocks and belong inside a complete Terraform resource.

## Expected behavior

A request selected by this route receives `503` and the “Scheduled maintenance” page. The body comes from the load balancer rather than the origin. A request to the example's normal `/` path is expected to continue to the healthy origin and return `200`.

The example contains a fixed message; it does not calculate recovery time or track maintenance progress. Keep any timing or support information accurate when you customize the body.

## Check the result

Request `/maintenance` on your configured host and inspect the status and message. Compare `/` on the same host for the normal `200` origin response. Confirm that the maintenance message appears only on the paths you selected, including after any other route rules are considered.
