## Purpose

Ask for verification where it is needed while allowing other requests to continue. F5 Distributed Cloud can select JavaScript or Completely Automated Public
Turing test to tell Computers and Humans Apart (CAPTCHA) verification through policy rules. Application-layer distributed denial-of-service (DDoS) protection
can also select a JavaScript challenge when its mitigation activates.

Custom wording explains the experience after selection. The selecting rule or mitigation event determines whether that experience should appear. Keep those two parts together when configuring and checking conditional challenges.

## When to use it

Use a policy rule for a known request condition, such as a sensitive path. The examples select exactly `/challenge` and use `no_challenge` as the default. Choose JavaScript verification for the browser-check variant or CAPTCHA for an interactive human check.

Use the DDoS variant when application-layer protection should choose the challenge during a mitigation event. You need supported challenge features and an existing load balancer. A DDoS check additionally needs an authorized mitigation exercise; requesting `/challenge` alone does not activate DDoS protection.

## Configure it

1. Choose the policy-selected or DDoS-selected mechanism that matches your requirement.
2. Set the challenge parameters and custom wording for that mechanism.
3. For policy selection, add the matching rule with its challenge action.
4. Set the policy default for requests that do not match.

These Terraform JavaScript Object Notation (JSON) fragments use provider block arrays. Each policy fragment includes both the parameters and selecting rule, so the message cannot be mistaken for a rule by itself.

## Expected behavior

The policy examples should challenge `/challenge` using the selected mechanism and allow `/` through the `no_challenge` default. A successful visitor should reach the application after completing verification. No fixed challenge status is assumed.

The DDoS example describes the challenge response when application-layer mitigation selects it. Its custom page does not prove mitigation activated. These are expected outcomes; the guide does not claim completed browser or mitigation demonstrations.

## Check the result

For policy selection, open `/challenge` in a fresh browser session and complete verification. Compare `/` without a verification cookie and confirm it bypasses
the challenge. Check the selecting policy rule for the challenged request. For DDoS selection, correlate the challenge with an actual mitigation event in your
authorized exercise and compare normal traffic outside that event.
