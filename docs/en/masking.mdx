title: Data masking

Masking reduces unintended disclosure without replacing the whole response. Selected-field rules target known JSON fields; Data Guard recognizes supported sensitive values. Use synthetic test data when checking either mechanism.

| Mechanism | Selection | Expected change |
| --- | --- | --- |
| Sensitive-data disclosure rule | GET `/sensitive` and named JSON fields | Selected values are hidden; other fields remain usable. |
| Data Guard rule | `/sensitive` with an attached application firewall | Supported sensitive values are masked in the selected response. |

## Selected JSON fields

> **Visitor response:** The usual JSON structure, with values in `card` and `ssn` hidden.

`sensitive_data_disclosure_rules` selects GET `/sensitive`, names the fields in `body.fields`, and chooses `mask`. Measure the replacement text rather than assuming a particular string.

## Data Guard

> **Visitor response:** Supported credit-card and Social Security numbers are masked.

A `data_guard_rules` path rule selects `/sensitive` and `apply_data_guard`. Recognition is supplied by Data Guard; the path rule does not define new patterns. This mechanism requires an application firewall attached through the load balancer's `app_firewall` reference.
