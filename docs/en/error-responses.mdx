Custom error mappings show a message for a status family or an exact code. The load balancer replaces the response body without changing the status.

| Mapping | Visitor message | Result |
| --- | --- | --- |
| `3xx`, `4xx`, or `5xx` (keys `3`, `4`, `5`) | “Class 3”, “Class 4”, or “Class 5” | Fallback for the status family. |
| Exact `503` | “Exact 503” | Overrides class `5` for `503`. |
| Exact `404` | “Exact 404” | Overrides class `4` for `404`. |

A mapping for key `3` can change the body of a `3xx` response; it does not create a redirect or change its `Location` header. Each encoded error body has a 65,536-character limit including the prefix. See [response-body encoding](../configuration-reference/#response-body-encoding) for the placeholder.

## Edge failures

An upstream connection reset or timeout may produce a different status from an origin error. Check the actual status before expecting a mapped body: these examples can return `500`, `502`, `503`, or `504`. When the mapping applies, each uses “Class 5.” The `/healthy` route reaches a healthy origin pool for comparison.
