**Scope: configuration-only.** These inactive alternatives explain how Bot Defense Standard would block a classified request or redirect a visitor on a protected endpoint. Live classification and mitigation are unavailable in this example.

Choose between endpoint-specific mitigation actions after Bot Defense classification; a fixed path response or WAF rejection has a different decision model.

Both examples protect POST `/bot-check` over a secure connection for web clients. They allow good bots, use the United States regional endpoint, and insert asynchronous JavaScript after the page's `<head>` element. Each endpoint chooses either `mitigation.block` or `mitigation.redirect`.

## Block response

> **Visitor message:** Request not accepted.

The block alternative uses `mitigation.block` with `status: Forbidden` and an encoded body. The body has a 4,096-character limit including its prefix. The Bot response has no confirmed `Content-Type` setting. See [response-body encoding](../configuration-reference/#response-body-encoding) to create your own message.
