Help visitors reach a resource that has moved. A load-balancer route redirects `/old` to `/new` over secure HTTP with status `302`; the destination application supplies the page.

## Prerequisites

An F5 Distributed Cloud Hypertext Transfer Protocol (HTTP) load balancer is the resource that receives application requests and selects routing or security behavior.

You need permission to edit an existing HTTP load balancer in its namespace and a test application you are authorized to configure. The destination must resolve and serve the intended content. Allow about 10–15 minutes for configuration, excluding provisioning and security-event testing.

## Configure

### Redirect a selected path

The caller receives status `302` and a `Location` ending in `/new`. A `302` redirect describes temporary movement. If method preservation matters, check your application clients' handling. Avoid a destination that redirects back to `/old`.

1. Save the previous settings for the fields you change.
2. Add a `redirect_route` for `/old` to the load balancer's `routes` list.
3. Set `route_redirect.proto_redirect` to `https`.
4. Set `route_redirect.path_redirect` to `/new`.
5. Set `route_redirect.response_code` to `302`.
6. Save the load balancer.

## Verify

1. Request `/old` without automatically following redirects.
2. Inspect status `302` and the `Location` header.
3. Open the destination.
4. Confirm its intended content.
5. Compare `/different` on the same host for the normal `200` origin response.
6. Follow the full redirect chain to confirm it terminates.

The route does not provide the destination page or guarantee its health.

## Clean up

Restore the previous route settings or remove only the redirect route you added. Preserve other routes, the load balancer and shared origin pools. Confirm the original path resumes its intended behavior.
