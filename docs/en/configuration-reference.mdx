The outcome pages show the fields relevant to each response. Their source-derived examples are resource fragments, not complete create or replacement requests.

## Resource fragments

Examples use JSON under `spec` with object and array types from the F5 resource schemas. Apply the illustrated fields to the existing resource while preserving its other settings. Routes and rules remain arrays; add entries without replacing unrelated entries. Choose the appropriate mutually exclusive response mechanism.

Replace `<APP_FIREWALL_NAME>`, `<ORIGIN_POOL_NAME>`, and `<XC_NAMESPACE>` with resource names and the namespace in your environment.

## Response-body encoding

`<ENCODED_RESPONSE_BODY>` marks a body field in a readable example. Replace it with `string:///` followed by canonical padded Base64 encoding of the UTF-8 body. The prefix counts toward the field's length limit. Body examples retain exact encoded values in expanded details. Decoded previews appear as escaped code, so their HTML is not executed or changed.

Preserve platform-controlled scripts and interactive elements in challenge bodies. The error-body `request_id` template is part of the source body.
