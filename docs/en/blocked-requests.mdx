Explain a security block in a format your callers can understand. Use a branded page for browsers or a structured message for application clients. The application firewall supplies the body after it decides to block a request.

## Prerequisites

An F5 Distributed Cloud Hypertext Transfer Protocol (HTTP) load balancer is the resource that receives application requests and selects routing or security behavior.

A web application firewall (WAF) inspects requests for threats. Its application-firewall resource owns `blocking_page`; the load balancer references that resource through `app_firewall`.

You need permission to edit both resources, an application firewall in blocking mode, and an authorized test request that its policy blocks. Keep a benign request for comparison. Allow about 10–15 minutes for configuration, excluding provisioning and security-event testing.

## Configure

### Choose the blocking format

| Format | Caller | Check |
| --- | --- | --- |
| Hypertext Markup Language (HTML) | Browser | Page readability and response media type. |
| JavaScript Object Notation (JSON) | Application client | Response media type and client parsing. |

These are alternative firewall configurations. The encoded `blocking_page` value has a 4,096-character limit, including its prefix. A JSON body alone does not establish `Content-Type`; verify the actual header with your client. Replace `<ENCODED_RESPONSE_BODY>` with your encoded message. See [response-body encoding](../configuration-reference/#response-body-encoding).

### Configure an HTML blocking page

> **Visitor message:** Request not accepted

1. Save the previous application-firewall blocking-page settings.
2. Set the application firewall's `blocking_page.response_code` to `Forbidden`.
3. Set its `blocking_page.blocking_page` to the encoded HTML body.
4. Save the application firewall.
5. Reference that firewall from the load balancer's `app_firewall` field.
6. Save the load balancer.

## Verify

1. Send the authorized request that the application firewall should block.
2. Confirm status `403` and “Request not accepted” in the body.
3. Inspect `Content-Type` for your chosen format.
4. Confirm the firewall recorded a blocking decision for the request.
5. Compare a benign `/` request for the normal `200` origin response.

For JSON, confirm the application client can parse the response. Repeat for each format you use; a fixed `403` from a route does not prove a WAF block.

## Clean up

Restore the previous blocking-page settings on the application firewall. If you changed the load balancer's firewall reference, restore its previous reference. Preserve the firewall's detection policy and any resources shared with other applications. Confirm benign traffic still reaches the origin.
