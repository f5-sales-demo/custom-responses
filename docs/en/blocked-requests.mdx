A web application firewall (WAF) supplies the blocking body after it decides to reject a request. Its application-firewall resource owns `blocking_page`; the load balancer references that firewall through `app_firewall`. The examples require a firewall in blocking mode and an authorized request that triggers its rule.

The encoded `blocking_page` value has a 4,096-character limit including the prefix. See [response-body encoding](../configuration-reference/#response-body-encoding) for the body placeholder.

## HTML blocking page

> **Visitor message:** Request not accepted

The firewall's `blocking_page.response_code` is `Forbidden`. Its `blocking_page.blocking_page` supplies the HTML body.

**Expected result:** A blocked request returns `403` with the readable page, and the firewall records a blocking decision. A benign request still reaches the origin. A fixed `403` from a route does not establish that the WAF blocked it.
