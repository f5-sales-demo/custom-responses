A policy rule can select JavaScript or human verification for a sensitive path. The human-verification option is a CAPTCHA, short for “Completely Automated Public Turing test to tell Computers and Humans Apart.” Application-layer distributed denial-of-service (DDoS) mitigation can also select JavaScript verification during an event.

| Alternative | Selector | Comparison |
| --- | --- | --- |
| Policy JavaScript | Exact `/challenge` rule | `/` bypasses verification. |
| Policy CAPTCHA | Exact `/challenge` rule | `/` bypasses verification. |
| DDoS JavaScript | Active application-layer mitigation | Normal traffic outside the event. |

See [response-body encoding](../configuration-reference/#response-body-encoding) for the custom-page placeholder. Keep the JavaScript verification script or CAPTCHA controls usable when customizing a challenge message.

## Policy-selected JavaScript challenge

> **Visitor message:** Please wait while your browser is verified.

`policy_based_challenge.js_challenge_parameters` supplies the page and parameters. A rule matching exactly `/challenge` selects `enable_javascript_challenge`; `no_challenge` is the default. A valid verification cookie can let a returning visitor continue without repeating the challenge.

## Policy-selected CAPTCHA

> **Visitor message:** Please complete the verification to continue.

`policy_based_challenge.captcha_challenge_parameters` supplies the page and cookie lifetime. An exact `/challenge` rule selects `enable_captcha_challenge`, with `no_challenge` as the default.
