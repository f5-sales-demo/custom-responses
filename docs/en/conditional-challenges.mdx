Ask for verification only where it is needed. A policy rule can select JavaScript or human verification for a sensitive path. Application-layer distributed denial-of-service (DDoS) mitigation can select JavaScript verification during a mitigation event.

## Prerequisites

An F5 Distributed Cloud Hypertext Transfer Protocol (HTTP) load balancer is the resource that receives application requests and selects routing or security behavior.

You need permission to edit an existing HTTP load balancer in its namespace and a test application you are authorized to configure. You need supported challenge features and a browser for verification. For DDoS, you also need an authorized mitigation exercise. Allow about 15–20 minutes per variant for configuration, excluding provisioning and security-event testing.

Completely Automated Public Turing test to tell Computers and Humans Apart (CAPTCHA) verification requires the visitor to complete an interaction.

## Configure

### Choose the selection mechanism

| Variant | Selection | Comparison |
| --- | --- | --- |
| Policy JavaScript | Exact `/challenge` rule | `/` bypasses verification. |
| Policy CAPTCHA | Exact `/challenge` rule | `/` bypasses verification. |
| DDoS JavaScript | Active application-layer mitigation | Normal traffic outside the event. |

Replace `<ENCODED_RESPONSE_BODY>` with your encoded message. See [response-body encoding](../configuration-reference/#response-body-encoding).

### Select JavaScript verification with a policy

> **Visitor message:** Please wait while your browser is verified.

1. Save the previous settings for the fields you change.
2. In the load balancer's `policy_based_challenge`, set `js_challenge_parameters` to your message and parameters.
3. Add a `rule_list.rules` entry matching exactly `/challenge`.
4. Select `enable_javascript_challenge` in that rule.
5. Set `no_challenge` as the policy default.
6. Save the load balancer.

### Select CAPTCHA verification with a policy

> **Visitor message:** Please complete the verification to continue.

1. Save the previous settings for the fields you change.
2. In the load balancer's `policy_based_challenge`, set `captcha_challenge_parameters` to your message and cookie lifetime.
3. Add a `rule_list.rules` entry matching exactly `/challenge`.
4. Select `enable_captcha_challenge` in that rule.
5. Set `no_challenge` as the policy default.
6. Save the load balancer.

### Select JavaScript verification during DDoS mitigation

> **Visitor message:** Please wait while your browser is verified.

Requesting `/challenge` does not activate mitigation. Customize the challenge in the context of your application-layer DDoS protection settings.

1. Save the previous settings for the fields you change.
2. Set the load balancer's `l7_ddos_action_js_challenge` message and parameters.
3. Save the load balancer.

## Verify

### Check a policy variant

1. Open `/challenge` in a fresh browser session.
2. Confirm the selected challenge message and interaction.
3. Complete verification.
4. Confirm navigation to the application.
5. Request `/` without a verification cookie.
6. Confirm it bypasses verification.
7. Confirm the selecting policy rule matches the challenged request.

Repeat independently for JavaScript and CAPTCHA. No fixed challenge status is assumed.

### Check the DDoS variant

1. Run your authorized mitigation exercise.
2. Correlate the challenge with the actual mitigation event.
3. Complete browser verification.
4. Compare normal application traffic outside the event.

The custom wording alone does not show that mitigation activated.

## Clean up

Restore the previous policy challenge or DDoS action settings for the variant you changed. Remove only the test rules you added. Preserve shared policies and existing DDoS protection. Confirm the restored selection and normal application traffic.
