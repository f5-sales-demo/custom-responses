Use the outcome pages to identify the resource you edit. An F5 Distributed Cloud Hypertext Transfer Protocol (HTTP) load balancer receives application requests and selects routing or security behavior. It owns error mappings, routes, challenges, Bot settings, response metadata and masking rules. The application firewall referenced by the load balancer owns its blocking page.

## Resource fragments

The examples use JavaScript Object Notation (JSON) under `spec`, with the object and array types from the official F5 resource schemas. Each fragment shows fields to modify on an existing resource. It is not a complete create or replacement request. Preserve your resource's other settings and select the appropriate mutually exclusive choice when changing a response mechanism.

Replace `<APP_FIREWALL_NAME>`, `<ORIGIN_POOL_NAME>` and `<XC_NAMESPACE>` with the referenced resource name and namespace. Routes and rules remain arrays; merge the illustrated entries into the existing lists rather than replacing unrelated entries.

## Response-body encoding

Primary examples use `<ENCODED_RESPONSE_BODY>` to keep configuration readable. Replace it with `string:///` followed by canonical padded Base64 encoding of your UTF-8 message. The prefix is part of the value and counts toward the field's length limit. Each outcome states any relevant limit beside its procedure.

Expanded details show the exact encoded projected values and decoded source body as code. Code previews display the body without executing its HTML or changing its bytes. Preserve platform-controlled scripts and interactive elements when customizing challenge messages. The error-body `request_id` template remains part of the source body.
