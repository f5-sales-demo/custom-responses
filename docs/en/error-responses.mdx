An error map gives visitors a recognizable explanation when a request fails. The load balancer selects a body by status class or exact status and keeps the original response status.

| Mapping | Visitor message | Result |
| --- | --- | --- |
| Class `3`, `4`, or `5` | “Class 3”, “Class 4”, or “Class 5” | Fallback for the status family. |
| Exact `503` | “Exact 503” | Overrides class `5` for `503`. |
| Exact `404` | “Exact 404” | Overrides class `4` for `404`. |

Class `3` replaces an eligible body; it does not create a redirect or change its destination. Each encoded error body has a 65,536-character limit including the prefix. See [response-body encoding](../configuration-reference/#response-body-encoding) for the placeholder.

## Edge failures

A connection reset, unavailable upstream, or timeout can follow a different path from an origin error. Check the failure you depend on; the edge examples expect `500`, `502`, `503`, or `504` with “Class 5,” according to the status produced. The comparison route uses a healthy origin pool for `/healthy`.
