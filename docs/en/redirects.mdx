Move a resource while controlling request method, body and query handling. A redirect route returns a status and `Location`; the destination application serves the final response.

> **Visitor response:** A redirect followed by the destination response.

| Status | Move | Method and body |
| --- | --- | --- |
| `302` | Temporary | Clients may change POST to GET. |
| `307` | Temporary | Method and body preserved. |
| `308` | Permanent | Method and body preserved. |

The `302` and `307` examples retain the query; the `308` example removes it. Removing the query is this example's `remove_all_params` setting, not an inherent property of `308`. Permanent redirects can be cached by clients.

## Compare a fixed POST

**Verified live example:** [Open the application demo panel](https://custom-responses.f5-sales-demo.com/demo/panel).

1. Select **POST through 307** to send a fixed synthetic body with `?sample=synthetic`.
2. Inspect the echo: its method is POST, its body is preserved, and its query contains `sample=synthetic`.
3. Select **POST through 308** to send the same input through the permanent alternative.
4. Inspect the echo: POST and the body remain, but the query is empty.

The application panel runs on the destination's own origin. Every action requires a click and reserves two requests against a twelve-request page budget. It reports the final echo; use the browser's network inspector with **Preserve log** to inspect the initial status and `Location`.

**Expected result:** The first response matches the selected status and destination; the final echo confirms the method, body and query behavior. An unrelated path still reaches the origin.
